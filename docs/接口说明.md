# AOM REST API 说明

接口为同源 `/api`，请求/响应均为UTF-8 JSON，导出CSV除外。写请求 `Content-Type: application/json`，最多3MiB；浏览器跨源写入被拒绝。业务接口要求管理员登录Cookie；HTTP只允许回环访问，局域网须HTTPS。客户端代理头不能放宽传输检查。

## 并发控制与请求规则

先 `GET /api/state` 获得状态及revision。所有写请求在根级携带该revision。成功返回新的完整State（含递增revision）；修订号已过期时返回409。字段使用模型中的camelCase，规划JSON采用snake_case命名。

```json
{"message":"数据已被其他操作修改，请刷新后重试"}
```

400为输入/业务校验失败；401为未登录/会话过期或凭据错误；403为跨源写入或不安全的远程HTTP；404为不存在的路径/审计；409为数据修订冲突；415为非JSON写请求；429为登录尝试过多；503为加密持久化失败；500为存储错误，细节只写后台日志。未知API路径/不支持的方法不会返回前端HTML。部分资源写操作的“记录不存在”属于400业务错误。

## 设备例子

```json
{
  "revision": 1,
  "autoPlace": true,
  "device": {
    "assetTag": "SERVER-001", "name": "业务服务器01",
    "modelId": "model-r722", "moduleId": "从state读取实际ID",
    "rackId": "", "startU": 0,
    "ip": "", "sn": "", "status": "pending", "note": ""
  }
}
```

型号角色：server/core/aggregation/access/management/storage/infra。uHeight整数0–42，0表示未确认。设备状态：pending/installed/maintenance。未上架必须rackId空、startU=0；已上架必须合法U高、不重叠且机柜属于目标模块。

## 数据一致性与范围

正式入口使用内存SQLite、外键、单连接写入与事务；状态与审计校验后加密保存到app.vault，磁盘上不新建明文业务库。当前目标规模上限10000设备/1000柜/1000型号，审计存完整前后快照，会随变更增长，需要定期关注磁盘空间。

网络和链路接口见下文。端口面板、工单与备件API尚未实现；型号端口文字说明不用于校验实际端口规格，物理端口占用以链路表为准。没有快照恢复或数据库上传接口。

## 项目与列内设施

State中projects数组包含id/name，sites包含projectId。Plan支持project_id选择已有项目或project_name创建新项目。未提供项目字段时使用第一个项目；同一项目内机房名称唯一。向已有机房增加模块时project_id必须匹配该机房。

Module包含productModel和point；ModulePlan相应字段为product_model和point。单/双排与柜数在创建时指定；修改接口不调整现有柜数量。

Infrastructure格式：

```json
{"id":"由服务端生成","moduleId":"模块ID","name":"右列空调01","kind":"ac","side":"R","afterRack":2,"placement":"inline"}
```

kind支持ac/power/env/ups/battery；side为L或R；inline的afterRack为0至该列柜数，integrated为1至该列柜数。每模块最多48项。JSON规划layout使用after_rack命名，字段其余含义相同。layout为空数组表示没有设施；null或省略时按infra数量生成示意位置。

导出规划不携带数据库内部项目ID；复用到现有项目时应明确提供project_id，或在向导中选择目标项目。

## 网络接口

| 方法 / 路径 | 输入 / 输出 |
| --- | --- |
| POST /networks | `{revision, network}`；创建网络分区 |
| PUT /networks/{id} | `{revision, network}`；更新信息与成员，projectId保留 |
| DELETE /networks/{id} | `{revision}`；被链路引用时拒绝 |
| POST /links | `{revision, link}`；创建手工链路，origin由服务端设置manual |
| PUT /links/{id} | `{revision, link}`；保留projectId和origin，可修改端点及确认状态 |
| DELETE /links/{id} | `{revision}`；删除链路并记录审计 |
| POST /topology/preview | `{revision, networkId}`；返回`{revision, links}`，不写库 |
| POST /topology/commit | `{revision, networkId}`；重算推演、原子提交，返回State；无候选时拒绝空提交 |

Network字段：id、projectId、name、purpose（business/management/storage/interconnect/other）、vlan（0–4094）、cidr、gateway、color（#RRGGBB）、deviceIds、note。

Link字段：id、projectId、sourceId、targetId、sourcePort、targetPort、networkIds、kind（physical/logical）、medium、speedGbps（0代表未知）、status（pending/confirmed）、origin（manual/inferred）、note。

链路端点必须同项目，选定网络的成员必须包含两端。已确认物理链路两端端口必填；已填物理端口在待确认时也独占。逻辑关系按无方向设备对唯一；物理多线缆可用不同端口重复连接一对设备。不存在的网络/链路编辑请求返回400业务错误。所有错误保持状态和审计不变。

网络列表、链路列表通过GET /state获得；图形层的JSON导出由前端生成，包含当前项目全部设备与网络连接，无服务端导入接口。

## 机柜排列与信息

`POST /modules/{id}/rack-insert`：输入`{revision,rackId,side,beforeId}`。rackId必须是该微模块的机柜，beforeId为目标列中的机柜或独立设施ID，空字符串表示列尾。按完整混排序列移除当前机柜再插入指定位置，其他柜子和独立设施的相对顺序保持不变；设施afterRack/order随新顺序计算，柜内集成设施仍附着原机柜。单排1–24柜，双排每列1–12柜，不增加或删除机柜；名称、资产、U位和网络连接保留。状态与审计原子保存，失效落点返回400，旧revision返回409。

`PUT /racks/{id}`：输入`{revision,name}`。名称1–80字符，同模块不重复。仅改名，容量和机位保留。

规划导出每模块包含`rack_names:{L:[名称...],R:[名称...]}`。导入可选提供该字段，数量须对应列柜数；未提供时自动生成名称。机柜顺序使用side/index。

## 子网络与直接移动

Network包含parentId（根级空）、devicePositions（deviceId→{x,y}）及可选position。Device包含可选topologyPosition，用于未分区节点。坐标范围0–10000，必须有限；网络设备坐标只能引用该网络直接成员。网络父级须同项目，最多8层且不得循环。

| 方法 / 路径 | 输入 / 语义 |
| --- | --- |
| POST /networks/{id}/move | `{revision,parentId,position}`；调整父级/结构位置，position可为null |
| POST /networks/{id}/position | `{revision,deviceId,position}`；只更新该成员的图位置；position=null恢复自动布局 |
| POST /devices/{id}/topology-position | `{revision,position}`；保存未分区图位置，不改变机位 |
| POST /network-members | `{revision,deviceId,sourceId,targetId,mode}`；mode为add/move/remove |

add要求有效targetId；remove要求设备属于sourceId；move要求源/目标为设备同项目的不同网络。移动/移出清理源网络位置及相关链路中的源网络标签，保留其他标签、线缆、端口、资产和物理机位；不自动添加目标链路标签。操作全部在revision事务中完成，并审计。

DELETE /networks/{id}要求不存在子网络、成员或链路引用。普通PUT网络详情保留服务端图位置字段，移除成员时清理其图位置；普通设备PUT保留已有图位置。

## 布局模板API

| 方法 / 路径 | 输入 |
| --- | --- |
| POST /templates | `{revision,template:{name,description,plan}}`；可选moduleId从现有模块捕获plan |
| PUT /templates/{id} | `{revision,template}`；整条修改模板，不改变任何已建实例 |
| DELETE /templates/{id} | `{revision}`；只删模板，保留实例 |

Template含id/name/description/plan/updatedAt；id及时间由服务端生成。plan为ModulePlan，固定42U，最多48设施，单排1–24柜或双排每列1–12柜。模板库全局共享、名称唯一、最多200个。State.templates提供列表；前端导出只含name/description/plan，格式aom-module-template/version=1。

## 初始化API

POST /initialize/preview 和 POST /initialize/commit 输入：

```json
{"revision":1,"projectId":"项目ID","siteId":"已有机房ID或空","siteName":"新机房名称","modules":[{"templateId":"布局模板ID","moduleId":"已有模块ID或空","name":"模块名","content":"设备CSV文本"}],"linksCSV":"可选连接CSV","infer":false}
```

每个模块选templateId新建或moduleId复用；已有模块须属于目标机房。设备列model/quantity等沿用CSV解析，额外networks/网络/所属网络/网络分区按分号分隔网络名称。已有同项目同名网络复用，新网络创建为other、VLAN=0且CIDR/网关空。

预览返回revision/siteId/newModules/devices/placed/pending/networks/links/rows/warnings/state（模拟结果），不持久化。提交重算并在单事务写入State与审计，201返回新State。旧revision返回409，校验错误400，无部分导入。预览后数据变化必须重做；同模块且批次设备来源指纹仍存在时，规范化相同清单拒绝重传；固定编号/SN全局唯一。缺少来源指纹或内容已变的文件不能仅依赖指纹去重。

连接CSV必填source/target，按资产编号引用同项目设备。可选source_port/target_port/kind/speed/medium/networks/status，支持中文列头；速率Gbps，默认physical/pending，实际确认须两端端口。网络标签要求两端成员已声明。infer只对本次清单涉及的网络生成待确认逻辑连接，可能引用该网络的已有上层设备。

总CSV2MiB、最多8模块、2000展开设备和2000明示连接。HTTP总请求3MiB，所有新增对象仍受全库容量与引用约束。

## 总清单字段与处理规则

InitRequest包含：projectName（projectId为空时创建项目）、unifiedCSV、defaultTemplateId、defaultModuleName、networksCSV、allowNewModels。unifiedCSV与modules列表互斥，总清单按module/模块名称分组，同名目标机房模块自动复用，新模块使用template/布局模板列或defaultTemplateId。

设备CSV支持asset_tag/资产编号（数量1）、rack/机柜、start_u/起始U（数量1且机柜必填）。明确U位先分配，自动排位随后进行。固定编号预留优先于自动编号。IP/SN/起始U/固定编号不得用于多台批量行。model/quantity仍必填。

role/设备角色、u_height/U高、vendor/厂商可声明型号；allowNewModels=true时未知型号必须有明确合法角色，U高缺省0。已存在型号的非空角色/U高与库冲突时拒绝，不更新已有型号。

networksCSV含network_name/网络名称、parent/上级网络、purpose/用途、vlan、cidr/网段、gateway/网关和可选color/颜色。最多200行，先登记网络后解析父级，验证同项目与无环。既有字段明确且不同则拒绝；空/未指定字段可补充。明示链路继续用资产编号引用，允许直接引用本次固定编号。

InitPreview包含projectId、newModels和resolvedModules（id/name/existing）；预览中的新内部ID为临时值，提交会重算，不能用其ID作为实际新建资源ID。返回的总清单错误/预览行号映射到原文件行号，包括带引号换行的单元格。

设备Source记录规范化清单哈希（目标moduleId、规范化列名/顺序与行数据）。同模块已有相同指纹的设备时拒绝重复批次；实际资产删除后指纹不再作为独立批次历史持久化。提交仍使用revision原子事务。

## 机房位置图与列间设施定位

Module.roomPosition为可选`{x,y}`坐标，范围0–10000且必须有限，表示机房示意图上的位置。空值由前端自动排布。ModulePlan使用room_position导出/载入机房规划；保存布局模板时不携带此坐标。

| 方法 / 路径 | 输入与语义 |
| --- | --- |
| POST /modules/{id}/room-position | `{revision,position:{x,y},rotation}`保存位置和可选方向；rotation为0/90/180/270，省略保留方向；position=null恢复自动排列 |
| POST /infrastructure/{id}/placement | `{revision,side,afterRack,beforeId}`移动独立设施，beforeId可空 |

设施位置接口只接受placement=inline的记录，且不能改变所属模块。目标列和afterRack必须在该模块范围内。beforeId指定同模块、同列、同柜间位置的另一独立设施，表示插到它之前；空值表示追加在目标位置的设施之后。

Infra.order和规划InfraSlot.order为同位置顺序，范围0–48，省略表示0。接口按目标设施顺序统一赋值，渲染按order稳定排序。详细编辑保留已有顺序；模板和机房规划导出均包含非零order。

模块改名保持roomPosition，跨机房归属变更清除roomPosition。机房示意位置不记审计，实际设施位置变更保存审计，旧revision返回409，非法坐标、目标列或设施引用返回400并保持原状态。模块重叠提示属于前端示意交互约束，不等同于工程尺寸碰撞检查。

## 登录接口

| 方法 / 路径 | 输入 / 输出 |
| --- | --- |
| GET /auth/status | 返回authenticated/setupRequired/username/encrypted；设置时可报告legacyAvailable，登录后可报告legacyFilePresent；不返回业务内容 |
| POST /auth/setup | `{token,username,password,importExisting}`；使用控制台初始化令牌创建管理员和加密文件，仅首次有效；201建立会话 |
| POST /auth/login | `{username,password}`；解锁/验证加密文件，200建立HttpOnly会话Cookie |
| POST /auth/logout | `{}`；需要已登录会话，撤销当前令牌并删除Cookie |
| POST /auth/password | `{currentPassword,newPassword}`；需要登录，验证当前密码后重加密，200返回reauthenticate=true，全部会话失效 |

认证请求最多4KiB。账号限定3–64位字母数字及._-；新密码12–128字节。setup检测app.db时必须显式勾选importExisting，不默默忽略现有数据。无账号/会话或加密文件损坏时不得访问业务接口，也不回退明文数据库。

会话8小时绝对过期、30分钟业务空闲过期。status轮询不延长空闲时间。每来源15分钟最多10次验证尝试，整体窗口最多60次；成功后清除该来源失败计数。无持久化会话，重启失效。

除静态页面、基础health和认证入口外，台账、审计、导出等全部在会话检查之后执行。业务代码不提供可由命令行启用的免登录模式。CSRF防护使用SameSite Strict Cookie、JSON写请求及严格Origin/Fetch-Site检查。

Module.roomRotation记录机房图方向，ModulePlan.room_rotation用于规划导出和复用。旋转只影响图形排列，不改变柜列、设备机位或连接。布局模板不保存机房实例的坐标和方向。

### 网络批量操作

`POST /api/network-members` 支持 `{revision, deviceIds: [设备ID], sourceId, targetId, mode}`，原单设备字段 `deviceId` 也可使用。`mode` 为 add / move / remove；最多2000台，每批一个事务与审计，任一失败整批回滚。

`POST /api/links/batch` 接收 `{revision, networkId, sources: [上联设备ID], targets: [下联设备ID]}`。设备须是该网络直接成员，上联1–8台，组合最多2000条。已有同网络的双端关系跳过；其余创建 manual 来源、pending 状态的 logical 关系，不填写端口或速率。全重复、设备重复、自连接、非成员和修订冲突均返回错误，不写入部分结果。

### 自动排列网络图

`POST /api/topology/auto-layout` 接收 `{revision, projectId, networkIds: [当前网络范围ID], deviceIds: [当前显示设备ID]}`。清除指定网络中指定设备的手动坐标；无任何网络归属的指定设备清除独立拓扑坐标。最多2000台设备、1000个网络；验证同项目与修订号，一次事务及审计。成员、连接、机位和其他范围坐标保持不变。前端根据可用宽度和实际角色自动排列。

### 审计精简

`POST /api/audits/compact` 接收 `{revision}`，返回 `{recordsBefore, recordsAfter, removed, compacted, bytesBefore, bytesAfter, warning?}`。容量表示审计正文JSON字节数，包含所有历史记录，不只界面的最近200条。只删除纯视觉/未变化记录，业务记录转换为变化对象格式；未知格式原样保留。业务状态与revision不变，修订冲突返回409，加密保存失败回滚。

审计明细before/after中的`format: changed-records-v1`表示只包含本次变化的对象数组；不存在于某一侧的对象对应新增/删除，未出现的集合没有变化。图形坐标、机房示意旋转、网络配色、模板更新时间不会进入审计。设备机位、设施安装位置、网络结构与连接仍记录。

### 网络分区图位置

`POST /api/networks/{id}/layout-position` 接收 `{revision, position: {x,y} | null}`。坐标范围0–10000，null恢复自动位置；只修改网络自身的position，不改变parentId、deviceIds、设备相对坐标、链接或机位。旧revision返回409，非法坐标返回400，纯视觉操作不产生审计。逐台拓扑与分组总览共用此位置。

`POST /api/topology/auto-layout` 同时清除networkIds指定网络的分区位置以及deviceIds指定设备在这些网络中的图坐标。网络层级与成员关系保留。

### 整组图位置保存

`POST /api/topology/device-positions` 接收 `{revision, projectId, networkId, positions:[{deviceId,position:{x,y}}]}`。1–2000台设备须属于该项目及指定网络，未分区设备使用空networkId；坐标须在0–10000。整批一个事务，任一设备或坐标无效全部回滚。只修改图位置，不改变机位/网络成员/连接，不产生审计。

折叠组拖入网络复用`POST /api/network-members`的deviceIds批量参数。普通拖动使用move（未分区设备使用add），Shift拖动使用add保留其他网络归属。按完整网络归属和型号生成的折叠组仅是前端显示，不创建合并资产。

### 显示层

Network含可选`layers:[{id,name}]`及`deviceLayers:{设备ID:层ID}`。不填layers时使用core/aggregation/access/compute/other五层。每网络最多16层；设备映射只能指向本网络成员及有效层。

- `PUT /networks/{id}/layers`：`{revision,layers,deviceLayers}`，保存有序层配置与映射，清除本网络设备图位置后重排。
- `POST /networks/{id}/layer-members`：`{revision,deviceIds,layerId}`，一次1–2000台。layerId空恢复角色自动映射，其他值须存在；只清除所选设备图位置，保留角色/成员/链路。失败整批回滚。
- `DELETE /networks/{id}` 支持`{revision,detach:true}`，明确移除网络归属和链路标签，保留资产与连接。仍有子网络拒绝；未给detach时仍校验成员与引用。

### 机柜及微模块增删

- `POST /modules/{id}/racks`：`{revision,side,name}`，追加机柜；名称可空自动编号。单排L列1–24柜，双排每列1–12柜。
- `DELETE /racks/{id}`：`{revision,mode,removeFacilities,confirmName}`。mode=uninstall将设备保留在本模块待上架区；mode=cascade删除柜内设备及关联链路/成员引用，须confirmName与柜名一致。柜内设施标记须removeFacilities=true。双排某列删空时转单排、保留独立设施；模块最后一柜返回整模块处理提示，由前端使用模块删除接口明确确认。未传mode按空柜校验，不隐式删除占用内容。
- `DELETE /modules/{id}`：`{revision,mode,targetModuleId,confirmName}`。mode=migrate要求同项目其他模块，全部设备迁为目标待上架（maintenance状态保留），保留网络和链路，再删除模块/柜/设施。mode=cascade要求confirmName与模块名一致，删除模块全部设备（含待上架）、关联链路、网络成员及图坐标/层引用，再删除结构；网络实体、外部设备和连接不受影响。mode空或empty仅允许空模块。全部变更单事务、一条精简审计，409/持久化失败无部分结果。

### 机房入口及ELK排列保存

`PUT /sites/{id}/entrance`：`{revision, entrance:{side,offset}|null}`。side为north/south/east/west，offset为0–100的沿边百分比。null清除入口；更新时保留所有机房/模块数据并记录配置变更。

`POST /topology/arrange`：`{revision,projectId,groups:[{networkId,position,positions:[{deviceId,position}]}]}`。客户端计算后一次提交，验证同项目、成员关系、设备唯一、全部坐标0–10000；networkId空仅限未分配设备。全部校验通过才写入，失败无部分变更。只保存图坐标，不增加审计。客户端计算期间状态修订改变时须重试。

## 界面交互修复的接口行为

- `POST /topology/restore-membership`：输入 `{revision, projectId, networks, links}`。networks只恢复同一项目现有网络的deviceIds/deviceLayers/devicePositions，links只恢复现有链路的networkIds。全部校验后原子提交；不创建/删除资源、不修改设备或网络属性。界面用它撤销/重做最近一次成员移动；revision过期返回409，不能覆盖后续操作。
- `PUT /networks/{id}/layers`：仅修改层名保留手动坐标；有效层ID或层序改变的设备清除本网络手动坐标，其余设备保留。
- 编辑页绑定打开时revision。409后不能把刷新出的新revision配给旧整对象直接重试；需重新打开最新对象。
