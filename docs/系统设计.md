# 系统设计

## 1. 部署与数据架构

Go单进程、CGO关闭，Vue3/SVG前端构建后通过embed嵌入后台。目标机运行一个程序，浏览器通过本机或局域网访问，无外部数据库、CDN和前端服务依赖。

SQLite在内存中组织业务数据，单连接事务、外键和领域校验保证一致性。磁盘存放AES-256-GCM加密的 `data/app.vault`，内含完整当前状态和重要审计。密码通过PBKDF2-HMAC-SHA256、随机32字节盐、600000次迭代派生密钥；密钥不单独落盘。保存使用新nonce、临时文件同步后替换；失败回滚内存事务。

所有修改携带revision，修订不一致返回409。一个数据目录只允许一个后台进程；锁文件阻止重复启动。加密容器上限512MiB。加密保护磁盘文件，不保护已登录浏览器、解锁内存和明文导出。

## 2. 业务结构

| 对象 | 核心关系 |
| --- | --- |
| Project / Site | 项目包含机房 |
| Module | 属于机房，单双排、型号、点位、图位置及方向 |
| Rack | 属于模块，以side/index表示柜列，容量42U |
| Infrastructure | 属于模块，列内独立或柜内集成，afterRack/order表示位置 |
| Model / Device | 型号定义角色、U高；设备保存资产编号、IP/SN、模块、机柜和U位 |
| DeviceRole | 全局角色可改名、改色与自定义，baseRole保留默认分层及推演分类 |
| Network / Link | 网络机房范围、矩形嵌套结构、成员、可选排列层和图坐标；链路保存真实端点与网络标签 |
| ModuleTemplate | 可复用柜列和设施结构，不包含真实资产 |
| Audit | 时间、动作、摘要、revision及变化对象前后值 |

点位1单排、点位1双排和点位2单排属于同一主机房，使用C2000（SG6600）、C2000（SG6600）、C500（C500-40K）。默认5柜、4+4柜、4柜是规划示例。厂家标准组合、额定容量、工程尺寸、供电和可用U位按配置单及现场资料核实。

## 3. 空间规则

单排L列1–24柜；双排L/R各1–12柜。设备U位连续且不可重叠，U高未知或空间不足时保留待上架。机柜插入把机柜与独立设施视为同一顺序，其他对象相对顺序不变；柜内集成设施跟随所属柜。

已建模块支持新增和集中删除机柜/模块。删柜默认将设备留在所在机房共享待上架区，确认后清理柜内设施标记；双排删空一列转单排，保留另一列与独立设施，最后一个机柜在前端转为整模块确认。删模块可迁移全部设备到同项目其他模块所在机房的共享待上架区并保留网络和连接，或显式确认级联删除设备及关联链路/成员引用。只针对选中范围，不删除网络实体、型号、模板或外部设备。删除和扩容在单一revision事务中校验、审计，加密写入失败回滚。

机房图使用SVG等距投影，平面/立体共享坐标，支持0/90/180/270度方向。拖动只更新局部变换，松手保存；图位置与工程尺寸分开。浏览器可用宽高控制画布适配，缩放不改变业务位置。

## 4. 网络与显示分层

网络属于项目，可多网络成员，父子最多8层，禁止循环和跨项目。父子是组织结构，不自动继承VLAN、网段、成员或路由。设备型号角色用于默认分层及推演；网络内部的显示层是独立配置，不修改设备角色。

分层显示是浏览器中的网络级偏好，独立控制层名、分隔虚线与淡底纹，即时切换不发送写请求。历史layersVisible仅作为没有本地偏好时的初始值。设备排列始终由层定义和分配决定；切换显示不改变任何坐标、框尺寸或配置入口，且不受全局辅助说明隐藏样式覆盖。新网络默认隐藏层名，旧记录已定义自选layers时默认显示。设置页始终可定义1–16个排列层（id/name有序列表），按设备ID记录显式分配。未指定设备按角色匹配默认层，没有匹配层时进入末层。删除层时其设备恢复自动分层；层名修改保留手动图位置，只有有效显示层或层序改变的设备恢复自动位置。拖入层区域批量修改设备层，一次提交。

默认折叠型号、完整网络归属、当前显示层及直接连接特征相同的设备；核心与汇聚设备保留独立。折叠仅影响画图，不改变台账；连接按实际链路聚合计数，展开保留其他网络。最多300张可见卡片；超过时提示合并、筛选机房或搜索，不丢弃对象。设备和组可移动位置，跨网络拖放改变成员，Shift表示加入并保留来源。网络标题拖动只修改图位置，父框所有后代同步移动。内部网络的positionSpace=parent标记其position相对父框，旧全图位置不误作局部偏移；新放置关系通过明确表单修改。

删除网络需明确detach，保留设备及链路，只移除网络实体、成员关系及链路上的该网络标签；显式liftChildren可将直属子网提升到原上级，未指定时仍拒绝包含子网的删除。未分配设备独立显示在画布，默认可见。设备右侧连接点可建立待确认逻辑关系，已存在关系直接打开详情；物理双端口、速率等需人工核实。

## 5. 导入与模板

初始化三步：选择项目/机房、上传总清单、预览确认。CSV UTF-8按模块分组，已有同名模块复用，新模块按模板创建。已知机位优先，其他连续排位。设备编号/SN唯一，同模块保留批次时阻止同内容重复导入；清单新增/追加，不覆盖台账。

设备、网络参数和连接CSV在一个事务中创建；网络复用只补空参数，明确值冲突不覆盖。推演只生成待确认逻辑关系，不猜测端口和布线。单次8模块、2000设备、200网络参数、2000连接，总文本2MiB。

模板保存柜名、列数和混排设施，不含资产、网络和机房图坐标。模板变更不改既有实例。

## 6. 交互与导航

侧栏切换工作区，顶部统一显示项目及空间/网络路径。根入口保持当前工作区；编辑返回原范围，跨工作区定位提供返回入口。地址记录项目和对象层级，支持刷新及浏览器历史。

常用位置、状态、成员及单设备分层直接操作；网络创建与基本修改使用快捷面板，显示层与链路资料使用专用窗口，网络和链路删除就地确认。完整资产与高级网络资料使用详细页面。统一新建网络表单和图中放置预览，内部网络真实嵌在父框中。选择网络只确定操作对象，不过滤整张图，机房范围负责筛选；未知归属的旧空网络继续可见。选中对象明确高亮，详情关闭只收起，固定入口可恢复。辅助统计、工具和侧栏可折叠，偏好在浏览器保存。具体规则统一见[界面与交互设计说明](界面与交互设计说明.md)。

## 7. 审计、安全与输出

重要业务变化和状态同事务提交。审计只保存变化对象before/after，新增仅after、删除仅before；纯图位置、旋转、配色和无变化保存不记录。可精简历史冗余，不自动按年龄删重要记录。

单管理员、HttpOnly/SameSite会话、登录限流、写入同源检查。局域网要求HTTPS；可自动生成自签名证书或使用指定证书。会话最长8小时、业务空闲30分钟过期。密码修改重新加密并撤销会话。

图形导出在浏览器生成PNG、单页栅格PDF、SVG，复制完整SVG与样式，包含范围说明。批量机柜立面拼接，超大栅格限制内存，SVG保留矢量。规划/台账/拓扑/审计JSON等导出用于交换与追溯；完整备份通过停止后台后复制data目录完成。

接口字段、错误码和事务约束见[接口说明](接口说明.md)；现场操作见[使用说明](使用说明.md)和[网络拓扑使用说明](网络拓扑使用说明.md)。

## 8. 拓扑画布交互

参考React Flow官方[Panning and Zooming](https://reactflow.dev/learn/concepts/the-viewport)中区分画布平移、缩放、对象操作的方式，沿用项目现有SVG实现，目标机无需额外服务；ELK.js随前端资源打包，首次自动排列时本地加载。

拓扑画布占用工作区主要宽高，常用工具按网络、设备与连接、查看分组，统计和筛选放入辅助面板，底部工具条独立占位。默认真实100%比例，显式总览适配内容，Ctrl/Command滚轮按指针锚定缩放；详情占用可视区域但不改变节点排列与当前缩放，图形布局宽度以整个工作区为基准。网络内自动排位每行最多6张卡片，由用户决定是否显示分层及自定义名称，卡片仅展示识别信息。缩放只改变视口，不重排或修改对象位置，拖动仍采用冻结矩阵及松手提交。

### 自动布局参考与实现

程序示例参考：[React Flow - ELK.js Tree](https://reactflow.dev/examples/layout/elkjs)，对应布局引擎为[ELK.js](https://github.com/kieler/elkjs)。应用沿用Vue/SVG，不引入React；ELK用于计算设备连接相关的同层顺序，用户定义的排列层始终作为最终排序约束；显示开关只控制标识，不改变排列。网络和设备的位置在一次revision事务保存。

历史重叠坐标由显示布局避让，交互中拒绝网络分区重叠。正交连线路由枚举设备边界通道，避开矩形占位，标签始终锚定对应线段，空间不足时使用线上紧凑标记；图形平移缩放和移动预览不写库。机房使用全尺寸SVG摄像视口，按容器比例调整viewBox，连续平移，不以拉伸图形填满两侧。模板卡片使用相同高度的标题、示意区和操作区。

ELK.js按EPL-2.0使用，运行包licenses/elkjs包含许可、声明和未修改的JavaScript发行源码。自动排列最多1000台，超出时要求缩小网络范围。

删除交互使用同一个置顶确认窗口，计算在架/待上架设备、设施标记及跨范围关联链路数量。默认选择保留设备路径，级联删除须选择并勾选确认；错误与进度紧邻按钮。遇到修订冲突刷新数据并清除确认，避免依据旧数量执行破坏性操作。


### 机房共享待上架区

待上架列表按所在机房聚合所有微模块中 `rackId` 为空的设备，不复制资产、不新增库存表，也不迁移旧数据。记录保留原 `moduleId` 用于确定机房与既有引用；上架时由目标机柜更新 `moduleId/rackId/startU`。资产ID、型号、IP/SN、网络成员、显示层及链路不变。下架保留最近所在模块，可立即从同机房任一模块的共享池再次分配。

快捷机位按机房列出所有模块的机柜，默认当前选中柜；共享列表的“上架”只作用于当前柜，寻找首段连续空闲U位。未知U高、容量不足时禁用，最终保存继续使用已有revision事务及全局U位冲突校验。维护状态保留。设备录入与CSV预览仍使用明确目标模块进行自动排位，未排上的设备在机房共享池统一显示。
